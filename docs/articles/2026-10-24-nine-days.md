# MeshPoint: How an Off-Grid E-Reader Grew Up in Nine Days

*By TMGCONMAN · October 24, 2026*

> **In development.** This article covers work done after the public 1.6.5-mesh.1 release. These builds are not part of a public release yet.

On October 15, the mesh-messaging fork of CrossPoint Reader shipped as version 1.6.5-mesh.1: an Xteink X4 Pro e-paper reader that doubles as the screen and keyboard for a MeshCore LoRa radio, so a group can text each other far from any cell tower. It was a working proof of concept on a single device.

Nine days later, the project has become a complete off-grid companion. It now has two editions and builds for three hardware platforms. It plays Game Boy games, carries an offline encyclopedia and a first-aid guide, administers mesh repeaters, and presents conversations in a modern chat interface. This is the path it took to get there, step by step.

## Two editions, one codebase

The project produces two editions from a single codebase, selected at compile time by a build flag, so every improvement reaches both.

- **MeshPoint** is the full-featured build: the complete mesh client plus the e-book reader, Apps, games, a Game Boy emulator, offline Wikipedia and the Survival Guide.
- **MeshCore Dashboard** is the field build. A mesh-centred dashboard is the home screen, the games are left out, and the Survival Guide and Wikipedia sit at the top of Apps.

| Edition | Xteink X4 Pro | Seeed reTerminal Sticky | Xteink X3 / X4 |
| --- | --- | --- | --- |
| MeshPoint | Yes | Yes | — |
| MeshCore Dashboard | Yes | Yes | Yes |

The X3 and X4 share one firmware image; the full edition is reserved for the devices with external PSRAM, as the engineering notes below explain.

## October 15: Entertainment and Reference, Off the Grid

The first expansion landed the same evening as the public release. The goal was simple: a device you carry into the backcountry should be useful between messages, too.

**Game Boy emulator.** Built on Peanut-GB, an MIT-licensed emulation core, the emulator runs in its own FreeRTOS task, separate from the user interface. It offers on-screen touch controls, battery-backed saves (`.sav`) and save states (`.state`) stored alongside each game in a `/roms` folder. The e-ink panel redraws only when the image changes, which keeps play responsive and power use low. Original Game Boy titles are supported.

**Offline Wikipedia.** The reader opens Kiwix `.zim` archives, the compressed format used for offline copies of Wikipedia, from a `/wikipedia` folder on the SD card. Title search, working internal links, a random-article function and a recently-read list make it a genuine reference tool with no connection at all. A compact ZIM parser handles the archive, and the zstd 1.5.7 library handles decompression.

**Survival Guide.** Fifty-two first-aid and outdoor-skills topics are compiled directly into the firmware, searchable and cross-linked. Because nothing has to be loaded from the card, the guide is always there when it matters.

Each of these components is covered by automated host tests, which run on a development computer and catch regressions before firmware ever reaches a device.

## October 19: Full Control of the Mesh

Four days later, the reader reached near feature parity with the official MeshCore app, turning it from a messaging screen into a complete network management tool.

- **Mesh > Tools:** radio statistics, a log of recently heard packets, nodes heard but not yet added, auto-add rules, the Bluetooth PIN, regional radio settings, identity backup and restore, restart and factory reset.
- **Repeater and room-server administration:** telemetry, neighbour lists, a remote command-line interface, the access list, and route discovery and trace-route.
- **Contacts:** share a contact with nearby radios over the air, and discover or trace the route to it.

For a group in the field, this means checking a repeater's battery, seeing which nodes can hear each other, or tracing why a message took the path it did, all from the reader in your pocket. Under the hood it required the additional companion-protocol commands for statistics, tracing, path discovery, telemetry and binary requests, plus a decoder for Cayenne LPP, the compact format MeshCore sensors use to report telemetry. The whole update cost about 32 KB of flash, no additional RAM, and arrived with 16 new host tests.

## October 22: More Devices and a Mesh-First Home Screen

**Three hardware platforms.** The mesh client was ported to the Xteink X3 and X4, as one combined image that detects the hardware at boot, and to the Seeed reTerminal Sticky. The Sticky shares the X4 Pro's ESP32-S3 chip family and 8 MB of PSRAM, so it runs the full edition, emulator included. More people can now join a group with the hardware they already own.

**The Mesh Dashboard.** A new home screen built around the radio rather than the library. A status card shows the link state, contact and channel counts and the unread total. Below it sit up to four conversations, unread first, one-tap shortcuts to Chats, Contacts, Nearby and Advert (the broadcast that announces your node to others), a Continue Reading card and the standard tab bar. On the trail, everything that matters is one screen away.

**Deliberate, verified updates.** Mesh builds now update only when you choose to: flash a new image, or upload it over Wi-Fi and install it with Update from SD card, which verifies that the file matches the device before writing it. An official CrossPoint release can never overwrite the mesh firmware by surprise.

**Continuous integration.** Every push to the main development branches now triggers GitHub Actions, which compiles each edition for each supported device and publishes the firmware images by version. A new build is ready to download about fifteen minutes after a change.

## October 24: A Modern Chat Experience and a Smoother Emulator

The latest build refines the two things people use most: conversations and games. Both changes have been confirmed working on the device.

**Chat bubbles.** Conversations now look like any modern messaging app. Your messages sit on the right in solid black bubbles; incoming messages sit on the left in outlined bubbles, each with one square corner on the sender's side. Timestamps and delivery status appear above each bubble, and short conversations settle at the bottom of the screen, right above the compose field. On a monochrome e-paper panel, the black-and-outline contrast makes it immediately clear who said what. Because the SDK's standard list component cannot align rows or draw bubbles, the chat screen uses a purpose-built renderer that keeps the familiar scrolling, button navigation, tap and long-press behaviour.

**Companion battery level.** The companion radio reports its battery voltage once a minute. The reader converts it to a percentage with a standard lithium-polymer discharge curve, a lookup table that maps voltage to remaining charge, and shows it in the chat header, on the Mesh screen and on the home screen. On the home screen the value moves in 5% steps, so normal voltage fluctuations never trigger an unnecessary e-ink refresh. Knowing when the radio needs charging is no longer guesswork.

**Dashboard as a theme.** The full edition can now use the Mesh Dashboard as its home screen, selected in settings, with every game and app still available. One device covers both the trail and the tent.

**A smoother emulator.** A review of the emulator's code surfaced a hidden bottleneck: the power manager lowered the CPU clock from 240 MHz to 80 MHz after three seconds without input, so games slowed to roughly a third of full speed during dialogue and cutscenes. A running game now keeps the CPU at full clock speed, while battery saving still applies when a game is paused or in its menu. In addition, ROM bank 0, the first 16 KB of every game, is always mapped into memory and holds much of a game's most frequently executed code. It is now copied from external PSRAM into the chip's faster internal SRAM when memory allows. A dedicated host test confirms the copy leaves game behaviour unchanged, and on the device, play is noticeably smoother.

## Engineering notes: fitting it all in

**Every byte is accounted for.** Each device reserves a 6.25 MB application partition for the firmware. The full MeshPoint edition, with the mesh client, reader, games, emulator, Wikipedia and Survival Guide, fits on the X4 Pro with room to spare.

| Build | App partition used |
| --- | --- |
| MeshPoint, X4 Pro | 94.8% |
| MeshPoint, Sticky | 93.1% |
| MeshCore Dashboard, X3 / X4 | about 93% |
| MeshCore Dashboard, X4 Pro | about 92.5% |
| MeshCore Dashboard, Sticky | about 91% |

A full partition costs nothing in speed: the chip executes code from flash through a small on-chip instruction cache, so performance depends only on the code running at that moment.

**Bringing mesh to the ESP32-C3.** The X3 and X4 run on an ESP32-C3 with roughly 380 KB of usable SRAM and no external memory, compared with the X4 Pro's 8 MB of PSRAM. To fit Bluetooth, the Arduino core is rebuilt with only what the mesh client needs: the NimBLE stack in the central role, limited to a single connection. Memory is claimed only while the mesh link is active, and if a radio holds more contacts than memory allows, the client logs it and carries on with what fits rather than crashing. Features that need PSRAM, the emulator and the Wikipedia reader, stay on the X4 Pro and the Sticky, which is why the X3 and X4 run the MeshCore Dashboard edition.

## What it adds up to

Picture a three-day trip with no cell coverage. Each person carries a small MeshCore radio and a reader. At camp, the Mesh Dashboard shows who has checked in and which messages are new, and a glance at the header shows how much charge your radio has left. A scout ahead on the ridge sends a message; it relays through a repeater and lands in a clean chat bubble on everyone's screen. Someone twists an ankle, and the Survival Guide's first-aid steps are a few taps away, no signal required. That evening there is a book to finish, a Wikipedia article to settle a debate, or a Game Boy game by the fire, on a screen that uses power only when the page changes.

In nine days the project went from a single-device proof of concept to that complete off-grid companion. It now has two editions, builds for three platforms, delivers near-complete MeshCore functionality, and has a polished chat interface and a smooth-running emulator.
